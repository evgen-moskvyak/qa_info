🚀 Manual QA Knowledge Base

Усе необхідне для ручного тестування Web та Mobile додатків в одному місці

📚 1. Теорія та Базові Поняття (QA Theory)

SDLC та STLC (Життєвий цикл розробки та тестування)

SDLC (Software Development Life Cycle) — процес створення ПЗ від ідеї до підтримки (етапи: Вимоги -> Дизайн -> Розробка -> Тестування -> Реліз -> Підтримка).

STLC (Software Testing Life Cycle) — послідовність етапів процесу тестування:

  • Аналіз вимог (Requirement Analysis)
  • Планування тестування (Test Planning)
  • Розробка тест-кейсів (Test Design)
  • Налаштування середовища (Test Environment Setup)
  • Виконання тестування (Test Execution)
  • Закриття тестування (Test Closure)
Види та Рівні тестування

Рівні тестування:

  • Unit (Модульне): перевірка окремих функцій/класів розробниками.
  • Integration (Інтеграційне): перевірка взаємодії кількох модулів або сервісів.
  • System (Системне): перевірка продукту в цілому на відповідність вимогам.
  • Acceptance (Приймальне): перевірка бізнес-вимог замовником (UAT).

Основні види: Функціональне, Нефункціональне (продуктивність, безпека, надійність), Регресійне (перевірка після змін), Smoke (димове, швидка перевірка критичної базової функціональності), Sanity (перевірка конкретного виправленого фіксу).

Техніки тест-дизайну

Методи створення ефективних тест-кейсів з мінімальною кількістю комбінацій:

  • Еквівалентні класи (Equivalence Partitioning): поділ вхідних даних на класи, де система веде себе однаково. Тестуємо по одному представнику з класу.
  • Граничні значення (Boundary Value Analysis): перевірка на стиках класів ($min$, $min+1$, $max-1$, $max$). Наприклад, якщо поле від 1 до 100, перевіряємо 0, 1, 2, 99, 100, 101.
  • Попарне тестування (Pairwise): комбінування параметрів по два, щоб зменшити кількість тестів при багатьох змінних.
  • Стан/Перехід (State Transition): перевірка переходів між станами об'єкта (наприклад, статус замовлення: Створено -> Оплачено -> Скасовано).
Артефакти тестування: Bug Report та Test Case

Test Case: набір кроків та очікуваних результатів для перевірки конкретної фічі.

Структура якісного Bug Report:

  • Title (Заголовок): Коротко де, що сталося (Де: На сторінці логіну, Що: Кнопка "Увійти" не активна при заповнених полях).
  • Environment (Оточення): ОС, браузер, версія додатка, пристрій.
  • Steps to Reproduce (Кроки): 1. Відкрити... 2. Ввести... 3. Натиснути...
  • Actual Result (Фактичний результат): Що відбулося насправді.
  • Expected Result (Очікуваний результат): Як має бути згідно з вимогами.
  • Attachments (Докази): Скріншот, відео, логи.

Severity (Серйозність — вплив на систему): Blocker, Critical, Major, Minor, Trivial.

Priority (Пріоритет — терміновість виправлення для бізнесу): High, Medium, Low.

🌐 2. Web Testing (Веб-тестування)

Кліент-серверна архітектура та HTTP/HTTPS

Браузер (Клієнт) надсилає запит (Request) на сервер, сервер обробляє його і повертає відповідь (Response).

Методи HTTP:

  • GET — отримати дані з сервера.
  • POST — створити нові дані на сервері.
  • PUT / PATCH — оновити існуючі дані (повністю або частково).
  • DELETE — видалити дані.

Коди стану (Status Codes):

  • 2xx (успіх): 200 OK, 201 Created.
  • 3xx (перенаправлення): 301 Moved Permanently, 302 Found.
  • 4xx (помилка клієнта): 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found.
  • 5xx (помилка сервера): 500 Internal Server Error, 502 Bad Gateway, 504 Gateway Timeout.
Робота з Browser DevTools

Основні вкладки для QA в Google Chrome / DevTools (F12):

  • Elements: перегляд та зміна HTML/CSS DOM-дерева в реальному часі.
  • Console: перегляд помилок JavaScript, виконання власного JS-коду.
  • Network: аналіз трафіку, перевірка HTTP-запитів/відповідей (Payload, Headers, Response), імітація повільного інтернету (Throttling: Slow 3G).
  • Application / Storage: перевірка LocalStorage, SessionStorage, Cookies та кешу.
API Testing для Manual QA (Postman)

Тестування програмного інтерфейсу без графічного інтерфейсу (UI).

  • Використовуємо інструменти типу Postman або Swagger.
  • Перевіряємо структуру JSON/XML відповідей, коректність статус-кодів та заголовків (Headers).
  • Авторизація: Basic Auth, Bearer Token, API Keys, Cookies.

📱 3. Mobile Testing (Мобільне тестування)

Особливості платформ та типи додатків

Типи додатків:

  • Native (Нативні): написані спеціально під платформу (Swift/Obj-C для iOS, Kotlin/Java для Android). Найвища продуктивність.
  • Mobile Web: сайти адаптовані під мобільні браузери.
  • Hybrid (Гібридні): веб-додатки всередині нативної оболонки (наприклад, Ionic, React Native / Capacitor).

Головні відмінності від Web: різноманітність пристроїв, роздільних здатностей, версій ОС, обмеження батареї, пам'яті та мережі.

Специфічні види перевірок на мобільних пристроях
  • Interrupts (Переривання): вхідний дзвінок, сповіщення, дзвінок у месенджері (Telegram/Viber), витягування шторки, розрядка батареї, вимкнення живлення. Додаток повинен коректно відновлювати стан.
  • Network connectivity: переключення Wi-Fi на 4G/5G, повна втрата мережі (офлайн-режим), слабкий сигнал.
  • Gestures (Жести): тап, сваїп, дабл-тап, пінч-ту-зум (збільшення двома пальцями), обертання екрана (Portrait / Landscape).
  • Updates & Installation: оновлення додатку поверх старої версії (backward compatibility), видалення даних, встановлення з маркетів.
Збір логів (Logcat та Xcode)

Android (`adb logcat`):

  • Встановити Android SDK Platform-Tools, підключити телефон по USB з увімкненим "USB Debugging".
  • Команда в терміналі: adb logcat для перегляду всіх системних логів у реальному часі.
  • Фільтрація за помилками: adb logcat *:E або за тегом/пакетом.

iOS (Xcode / Console.app):

  • Підключення через Mac, відкриття Xcode -> Window -> Devices and Simulators або використання програми Console для перегляду краш-логів (Crash Logs).

🛠️ 4. Інструменти та Практика

Git для QA (Базовий мінімум)

Основні команди, які потрібні тестувальнику для роботи з репозиторіями та проєктами:

  • git clone [url] — клонування репозиторію на локальний ПК.
  • git status — перевірка статусу файлів.
  • git checkout -b [branch_name] — створення нової гілки та перехід на неї.
  • git pull — оновлення локальної гілки з віддаленого репозиторію.
  • git add . — додавання змінених файлів до коміту.
  • git commit -m "message" — збереження змін.
  • git push — відправка комітів на GitHub.
Jira / Task Trackers

Інструмент для відстеження завдань та дефектів:

  • Epic -> Story -> Task -> Bug: ієрархія сутностей у проєкті.
  • Workflow (Життєвий цикл задачі/бага): To Do -> In Progress -> In Testing (QA) -> Done / Closed (або Reopened, якщо знайдено баг повторно).
